# Design Patterns

  We have Three types of deisgn patterns

## Creational Patterns (Object Creation)
  - Purpose: Control how objects are instantiated to avoid tight coupling.

  ### Common Patterns:

    **Singleton** 
    -  One instance globally (e.g., logging, configuration).

    **Factory**
    - Method → Delegate object creation to subclasses (e.g., payment gateways).

    **Abstract Factory** 
    - Create families of related objects (e.g., UI themes).

    **Builder** 
    - Step-by-step construction of complex objects (e.g., reports).

    **Prototype** 
    - Clone existing objects (e.g., caching templates).

  ### When to Use: When object creation is complex, expensive, or needs strict lifecycle control.

## Structural Patterns (Object Composition)
   - Purpose: Organize classes/objects into larger, flexible structures.
   ### When to Use: When you need flexibility, extension without modification, or to hide

## Behavioral Patterns (Object Communication)
  - Purpose: Manage communication and responsibilities between objects.
  ### When to Use: When behavior changes frequently or logic is conditional-heavy.
